# Switchy — спецификация

Личная утилита для macOS: ручной перевод текста между раскладками, прямые хоткеи раскладок,
память раскладки по окнам и история буфера обмена. Замена Caramba Switcher (без автопереключения
и словарей) и Input Source Pro (только прямые хоткеи).

- **Платформа:** macOS 26+ (Apple Silicon), только для себя, без App Store.
- **Язык/UI:** Swift 6, AppKit + SwiftUI (окно настроек).
- **Сборка:** Swift Package + скрипт `scripts/build-app.sh` → `Switchy.app`. Без `.xcodeproj`.
- **Без App Sandbox** (нужен глобальный перехват клавиатуры и управление раскладкой).
- **Права:** Accessibility (Универсальный доступ) и Input Monitoring (Мониторинг ввода).
- **Подпись:** стабильная идентичность (Apple Development от бесплатного Apple ID через Xcode или
  самоподписанный сертификат), чтобы права TCC не слетали при пересборке.
- **Вид:** иконка в строке меню с кодом текущей раскладки (EN / RU / UA), без иконки в Dock.

---

## 1. Перевод текста между раскладками

### 1.1. Свеженабранный текст

Приложение ведёт **буфер набора**: последовательность физических нажатий (keycode + Shift/CapsLock)
в текущем окне.

- **Попадают:** нажатия, дающие символ (буквы, цифры, знаки, пробел), без Cmd/Ctrl/Option.
- **Буфер сбрасывается:** Enter, Tab, Esc, Backspace, Delete, стрелки, Home/End/PgUp/PgDn, любое сочетание с Cmd/Ctrl/Option,
  клик мышью, смена окна/приложения, **смена раскладки извне** (вручную или системой).
  Смену раскладки самим Switchy при конвертации буфер не сбрасывает.
- **Пауза в наборе** дольше заданной (настройка, по умолчанию 5 с; «никогда» — выключено) тоже граница:
  следующее нажатие начинает новый фрагмент. Сам тап после паузы переводит последний фрагмент.
- **Что переводится:** настройка «Последнее слово» / «Весь фрагмент с последнего сброса».
  По умолчанию — весь фрагмент (типичный случай: набрал фразу не в той раскладке).

**Алгоритм:**
1. N раз Backspace (N — длина переводимого фрагмента).
2. Символы для целевой раскладки вычисляются самим Switchy из таблиц раскладок (`UCKeyTranslate`)
   и вводятся как Unicode-события. Это не зависит от того, успело ли приложение подхватить
   новую раскладку.
3. Системная раскладка переключается на целевую.
4. Буфер сохраняется — повторный хоткей переводит тот же фрагмент дальше по кругу.

### 1.2. Выделенный текст

Если буфер набора пуст, хоткей перевода работает с выделением:
1. Получить выделение: AX `kAXSelectedTextAttribute`, иначе — имитация Cmd+C
   (с сохранением и восстановлением содержимого буфера обмена).
2. Определить исходную раскладку по символам: для каждой раскладки считаем, сколько символов
   текста она умеет набрать; побеждает лучшая, при равенстве — текущая системная.
3. Целевая раскладка — следующая по кругу. Повторный хоткей (пока выделение то же) — дальше по кругу.
4. Заменить выделение вставкой (Cmd+V) с восстановлением буфера обмена. Свои записи в буфер
   помечаются служебным типом, чтобы не попадать в историю (раздел 4).
5. Переключить системную раскладку на целевую.

### 1.3. Круг раскладок

Порядок задаётся в настройках, по умолчанию **EN → RU → UA → EN**. Список берётся из включённых
в системе источников ввода. Буквы, которые различаются в RU и UA (`ы/і`, `э/є`, `ъ/ї`, `ё/'`, `ґ`),
переводятся корректно, потому что перевод идёт через физические клавиши.

### 1.4. Умный перевод

Настройка «Режим перевода»: **Умный** (по умолчанию) / **Просто по кругу**.

В умном режиме **первое** нажатие хоткея перевода выбирает раскладку автоматически:
1. Фрагмент рендерится во всех раскладках круга (для набранного — из keycode, для выделения —
   обратным маппингом символов в keycode исходной раскладки).
2. Каждый кандидат (кроме текущего/исходного) оценивается встроенными средствами macOS, без сети:
   - `NLLanguageRecognizer` — вероятность языка раскладки (en / ru / uk);
   - `NSSpellChecker` — доля слов, известных словарю этого языка.
3. Если лучший кандидат уверенно впереди (порог подбирается на реальных примерах) — переводим в него.
   Если уверенности нет (короткое слово, код, мусор) — ведём себя как «по кругу».

**Серия нажатий.** Второе и последующие нажатия (пока фрагмент не менялся и других клавиш не было)
идут по кругу, но **исходная раскладка — последней**. Пример для круга EN → RU → UA, набрано в EN,
умный выбрал UA: 2-е нажатие → RU, 3-е → EN (как было набрано), 4-е → UA и т. д.

Прямые хоткеи (раздел 2) умный режим не используют — они всегда переводят в указанную раскладку.

Вне рамок первой версии: локальная модель Apple (Foundation Models) как запасной оценщик для
неуверенных случаев.

## 2. Прямые хоткеи раскладок

Таблица в настройках: «хоткей → раскладка». По умолчанию F13 → English, F14 → Русский,
F15 → Українська.

- Нажатие гарантированно включает указанную раскладку (не по кругу).
- **Опция «Заодно перевести набранное»** (выключена по умолчанию): если буфер набора не пуст и
  текущая раскладка отличается от целевой — набранный фрагмент переводится **прямо в целевую**
  раскладку (как в п. 1.1), затем раскладка включается.
- С выделением прямые хоткеи не работают (чтобы случайное выделение не испортить).

## 3. Память раскладки по окнам

Switchy запоминает раскладку **для каждого окна**: `ключ окна → источник ввода`.

- **Ключ окна:** pid + CGWindowID фокусного окна (через Accessibility). Вкладки браузера и
  PhpStorm внутри одного окна — одно окно.
- **Запоминание:** при любой смене раскладки (через Switchy или вручную) — для текущего фокусного окна.
- **Восстановление:** при фокусе окна (смена приложения или окна внутри приложения) — если для него
  есть запись и она отличается от текущей раскладки.
- **Новое окно:** настройка «Оставлять текущую» (по умолчанию) / «Всегда English».
- Записи закрытых окон и завершённых приложений удаляются.
- Системную опцию «Автоматически переключаться на источник ввода документа» нужно **выключить**,
  чтобы система и Switchy не спорили. Switchy проверяет её при запуске и подсказывает.

Это и решает проблему Caramba: переключение, сделанное Switchy, запоминается так же, как ручное.

## 4. История буфера обмена (только текст)

- Опрос `NSPasteboard.changeCount` каждые ~0,4 с; берётся только текст.
- **Не сохраняется:** то, что помечено `org.nspasteboard.ConcealedType` / `TransientType` /
  `AutoGeneratedType` (менеджеры паролей и т. п.), служебные записи самого Switchy, пустые строки,
  содержимое из приложений из списка исключений.
- Дубликаты не плодятся: повторно скопированное поднимается наверх.
- Размер истории — в настройках (по умолчанию 50). Опция «Помнить после перезагрузки»:
  `~/Library/Application Support/Switchy/history.json` (по умолчанию включено).
- **Панель** по хоткею (настраивается; предлагаемый по умолчанию — Cmd+Shift+V с предупреждением
  о конфликте с PhpStorm и «вставкой без форматирования»):
  - появляется у текстового курсора (AX), иначе у указателя мыши;
  - не забирает фокус у текущего приложения (non-activating panel);
  - список: первые строки элемента, длинные обрезаны; 1–9 — быстрый выбор; стрелки + Enter;
    набор текста фильтрует список; Esc — закрыть; Delete — удалить элемент из истории;
  - выбор: элемент кладётся в буфер обмена и в исходное окно отправляется Cmd+V.

## 5. Хоткеи

Свой движок на том же перехватчике событий (CGEventTap). Типы хоткеев:

| Тип | Пример |
|---|---|
| Тап модификатора | тап правого Option (нажал-отпустил, без других клавиш, < 300 мс) |
| Двойной тап модификатора | двойной тап левого Option |
| Одиночная клавиша | F13 |
| Сочетание | Ctrl+Option+Space, Cmd+Shift+V |

Левые и правые модификаторы различаются. Сработавшие одиночные клавиши и сочетания поглощаются
(не доходят до приложения). Тап модификатора не поглощается, а обычные Option+буква работают как раньше.

## 6. Настройки

SwiftUI-окно, открывается из меню строки меню. Хранение — `UserDefaults`.

- **Хоткеи:** перевод текста; история буфера; таблица прямых хоткеев раскладок.
  Своё поле записи (умеет записывать тапы модификаторов и двойные тапы); предупреждение о конфликте
  с известными системными сочетаниями и с другими хоткеями Switchy.
- **Раскладки:** порядок круга (перетаскиванием), какие участвуют.
- **Перевод:** режим «Умный / Просто по кругу»; «последнее слово / весь фрагмент»;
  «прямые хоткеи переводят набранное».
- **Память окон:** вкл/выкл; поведение для новых окон.
- **Буфер обмена:** вкл/выкл, размер, хранить после перезагрузки, очистить историю.
- **Исключения:** приложения, где перевод и/или история отключены.
- **Запуск при входе в систему** (`SMAppService`).
- **Права:** статус Accessibility / Input Monitoring с кнопками открытия нужных разделов Системных настроек.

## 7. Меню в строке меню

Код текущей раскладки; пункты: «История буфера…», «Пауза» (временно отключить всё),
«Настройки…», «Выход».

## 8. Поведение и безопасность

- Поля паролей (Secure Input) — Switchy ничего не видит и не делает.
- Буфер набора хранится только в памяти и очищается при каждом сбросе; на диск не пишется никогда.
- Собственные синтетические события помечаются и игнорируются перехватчиком.
- Перехватчик, отключённый системой по таймауту, автоматически включается снова.
- Если прав нет — приложение работает в «спящем» режиме и показывает, что нужно включить.
