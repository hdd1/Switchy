# Switchy для Windows — спецификация для реализации

Этот документ — задание для разработчика (человека или ИИ-агента): сделать Windows-версию утилиты
**Switchy**. Оригинал — для macOS, открытый код: https://github.com/hdd1/Switchy (Swift, лицензия MIT).
Его можно и нужно читать как эталон поведения; ниже всё, что нужно, описано без знания Swift.

Документ описывает **что** должно получиться и **как оно себя ведёт**, а для каждой части —
рекомендуемые Windows API и известные подводные камни. Выбор языка и фреймворка — за реализацией
(рекомендация — в разделе 9).

---

## 1. Что это

Небольшая программа в системном трее, которая:

1. **Переводит текст, набранный не в той раскладке**, — по нажатию хоткея, **не автоматически**.
   Набрал `ghbdtn` вместо «привет» → нажал хоткей → текст перепечатан в правильной раскладке,
   раскладка переключена.
2. **Умный режим**: первое нажатие само выбирает наиболее вероятную раскладку (проверка орфографии +
   распознавание языка, всё локально, без сети). Повторные нажатия перебирают раскладки по кругу.
3. **Переводит выделенный текст** тем же хоткеем.
4. **Прямые хоткеи раскладок**: своя клавиша на каждую раскладку (например, F13 → English,
   F14 → Русский, F15 → Українська). По желанию (опция) заодно переводят только что набранное.
5. **Помнит раскладку для каждого окна**.
6. **История буфера обмена** (только текст) с панелью быстрого выбора по хоткею.
7. **Окно настроек**, интерфейс на английском, русском и украинском.

**Принципы:** никаких словарей, которые надо поддерживать вручную; никакой сети — ничего не уходит
с компьютера; никакого автопереключения «на лету» — только по явному действию пользователя.

---

## 2. Перевод набранного текста

### 2.1. Буфер набора

Программа ведёт **буфер набора** — последовательность **физических нажатий** (виртуальный код клавиши
/ скан-код + состояние Shift и CapsLock), сделанных пользователем в текущем поле.
Храним именно клавиши, а не символы: тогда перевод в любую раскладку — это «те же клавиши в другой
раскладке», без таблиц соответствия.

- **Попадают в буфер:** нажатия, дающие символ (буквы, цифры, знаки препинания, пробел) без
  Ctrl / Alt / Win. Автоповтор — тоже.
- **Буфер сбрасывается (граница фрагмента):** Enter, Tab, Esc, **Backspace**, Delete, стрелки,
  Home/End/PgUp/PgDn, любое сочетание с Ctrl/Alt/Win, клик мыши (любой кнопкой), смена активного
  окна/приложения, смена раскладки **не нашей программой** (вручную или системой).
- **Пауза в наборе** дольше заданной (настройка: никогда / 2 / 3 / 5 / 10 / 30 с, по умолчанию 5 с) — тоже
  граница: следующее нажатие начинает новый фрагмент. Сам хоткей после паузы переводит последний фрагмент
  (можно набрать, перечитать и только потом нажать).
- Длина буфера ограничена (500 нажатий — старые отбрасываются).
- Буфер живёт только в памяти, на диск не пишется никогда.

**Что переводится** — настройка:
- «Весь фрагмент» (по умолчанию) — всё содержимое буфера;
- «Последнее слово» — хвост после последнего пробела (вместе с пробелами в конце).

### 2.2. Алгоритм перевода

Дано: нажатия фрагмента, раскладка `from` (в которой он сейчас выглядит в поле) и целевая `to`.

1. `oldText` = нажатия, отрисованные в раскладке `from`; `newText` = те же нажатия в раскладке `to`.
2. Дождаться, пока пользователь **отпустит все модификаторы** (опрос с шагом ~20 мс, максимум ~1 с).
   Иначе приложение примет наш Backspace за Ctrl+Backspace / Alt+Backspace («удалить слово»).
3. Отправить `oldText.length` нажатий Backspace.
4. Ввести `newText` **Unicode-событиями** (а не повторным нажатием тех же клавиш после смены
   раскладки): результат не зависит от того, успело ли приложение подхватить новую раскладку.
5. Переключить раскладку активного окна на `to`.
6. Буфер **не очищается** — повторное нажатие хоткея переводит тот же фрагмент дальше.

Все синтетические события помечаются (поле `dwExtraInfo` в `INPUT`) и игнорируются собственным
перехватчиком клавиатуры. Действия выполняются строго последовательно (очередь), чтобы быстрые
повторные нажатия не перемешали ввод.

### 2.3. Серия нажатий и порядок раскладок

**Круг раскладок** — порядок из настроек (по умолчанию — порядок установленных в системе раскладок),
например `EN → RU → UA`.

Серия — повторные нажатия хоткея перевода над **одним и тем же** фрагментом (пока пользователь не нажал
другую клавишу и не кликнул). Порядок серии: **по кругу, начиная со следующей после исходной; исходная —
последней**. Если первый шаг выбран умным режимом или прямым хоткеем — он идёт первым, остальные по кругу,
исходная всё равно последней.

| Круг | Набрано в | Первый выбор | Серия |
|---|---|---|---|
| EN, RU, UA | EN | — (по кругу) | RU → UA → EN → RU … |
| EN, RU, UA | RU | — | UA → EN → RU … |
| EN, RU, UA | EN | UA (умный) | UA → RU → EN … |
| EN, RU, UA | UA | RU (прямой хоткей) | RU → EN → UA … |

Если после перевода пользователь продолжил печатать, переведённое считается принятым: серия
заканчивается, буфер очищается, новый фрагмент начинается с нового нажатия.

### 2.4. Таблицы раскладок

Нужны две операции для **любой** установленной раскладки:
- клавиша (+Shift/CapsLock) → символ;
- символ → клавиша (+Shift) — обратная таблица (для перевода выделенного текста).

Строить их из системных данных раскладки, не вручную. В обратной таблице при совпадениях побеждает
вариант без Shift и с меньшим кодом клавиши. Учитывать только «печатающий» основной блок клавиатуры
(без цифрового блока — он одинаков во всех раскладках). Мёртвые клавиши (dead keys) — вне рамок первой версии.

## 3. Умный режим

Настройка «Режим перевода»: **Умный** (по умолчанию) / **Просто по кругу**.

На **первом** нажатии серии:
1. Отрисовать фрагмент во всех раскладках круга, кроме исходной, — это кандидаты.
2. Оценить каждого кандидата:
   - `spell` — доля слов (из 2+ букв), которые словарь проверки орфографии **языка этой раскладки**
     считает правильными (0…1);
   - `lang` — вероятность языка раскладки по распознавателю языка (0…1). Распознавать **без
     ограничения** списка языков: если ограничить {en, ru, uk}, любой латинский мусор получает
     «английский» с вероятностью ~1;
   - `letters` — доля букв среди непробельных символов (варианты со знаками внутри слов — хуже).
3. `score = 0.7 * spell + 0.2 * lang + 0.1 * letters`.
4. Если лучший кандидат набрал `score ≥ 0.45` **и** опережает второго на `≥ 0.1` — переводим в него.
   Иначе уверенности нет — ведём себя как «по кругу».

Веса подобраны на тестах ниже. Ключевое: **словарь — главный сигнал**. Распознаватель языка ошибается
на коротких фразах (например, «Добрий день» считает русским на 97%), а словарь — нет.

### 3.1. Обязательные тестовые случаи

Формат: что пользователь **хотел** написать → в какой раскладке **набрал** → что должен выбрать умный режим.

| Хотел | Набрал в | Ожидаемый выбор |
|---|---|---|
| привет как дела | EN | RU |
| Съешь же ещё этих мягких французских булок | EN | RU |
| сегодня хорошая погода | EN | RU |
| привет | EN | RU |
| спасибо | EN | RU |
| привіт як справи | EN | UA |
| дякую за допомогу | EN | UA |
| привіт | EN | UA |
| Добрий день | EN | UA |
| hello world | RU | EN |
| the quick brown fox | RU | EN |
| hello | RU | EN |
| commit | RU | EN |
| привіт як справи | RU | UA |
| как дела | UA | RU |
| xq | RU | нет уверенности (по кругу) |
| a1b2 | RU | нет уверенности (по кругу) |

### 3.2. Тесты перевода раскладок (Russian/Ukrainian — «PC»-варианты, ЙЦУКЕН)

- `ghbdtn` (EN) → `привет` (RU); `Ghbdtn` → `Привет`; `ntcn 123` → `тест 123`.
- `руддщ` (RU) → `hello`; `Руддщ цщкдв` → `Hello world`.
- `ghbdsn` (EN) → `привіт` (UA); `]` → `ї`; `'` → `є`.
- RU → UA: `ы` → `і`, `ъ` → `ї`, `э` → `є`.
- Символы, которых нет в исходной раскладке (эмодзи), остаются как есть: `ghbdtn 👋` → `привет 👋`.
- Туда-обратно без потерь: «Съешь же ещё этих мягких французских булок» RU→EN→RU.

## 4. Перевод выделенного текста

Если буфер набора пуст (пользователь кликнул/двигал курсор после набора), хоткей перевода работает
с выделением:

1. **Получить выделение** без буфера обмена — через UI Automation. Если приложение не отдаёт
   выделение — запасной путь: сохранить буфер обмена, послать Ctrl+C, дождаться изменения буфера
   (до ~400 мс), прочитать текст, **вернуть буфер обмена как было**. Если UIA сообщает, что выделения
   нет — Ctrl+C **не** посылать (иначе некоторые редакторы копируют всю строку).
2. **Определить исходную раскладку**: для каждой раскладки посчитать, сколько **букв** текста она
   может набрать; побеждает максимум; при равенстве — текущая раскладка, иначе первая по кругу.
   (Латиница → EN; `ы э ъ ё` → только RU; `і ї є ґ` → только UA; «привет» — равенство RU/UA.)
3. Кандидаты и умный режим — как в разделе 3, текст переводится через таблицы: символ → клавиша в
   исходной → символ в целевой; неизвестные символы остаются как есть.
4. **Заменить выделение**: короткий однострочный текст (≤ 300 символов) — ввести Unicode-событиями
   поверх выделения; многострочный/длинный — вставить через буфер обмена (Ctrl+V), затем **вернуть
   прежнее содержимое буфера**. Свои записи в буфер помечать (раздел 6), чтобы они не попали в историю.
5. Переключить раскладку; повторные нажатия — серия (Backspace по длине вставленного + ввод следующего).

Прямые хоткеи раскладок выделение **не** трогают (чтобы случайное выделение не испортить).

## 5. Прямые хоткеи раскладок и память окон

### 5.1. Прямые хоткеи

У каждой раскладки — основной и дополнительный хоткей (по умолчанию `Ctrl+Alt+1`, `Ctrl+Alt+2`, …
по порядку раскладок; дополнительный не задан). Нажатие гарантированно включает эту раскладку
(и сбрасывает буфер набора, как ручная смена раскладки).
Опция «Заодно переводить набранное» (по умолчанию **выкл.** — от «переключить раскладку» обычно не ждут,
что изменится уже набранный текст): если буфер не пуст и текущая раскладка
другая — фрагмент переводится **прямо в эту раскладку**, затем она включается.

### 5.2. Память раскладки по окнам

Каждое окно (верхнего уровня) помнит свою раскладку; при переходе в окно она восстанавливается.
Запоминаются **любые** переключения — ручные и сделанные программой.

> ⚠️ На Windows раскладка по умолчанию и так **своя у каждого потока/приложения** (если в
> «Параметры → Время и язык → Ввод → Дополнительные параметры клавиатуры» не включено «Использовать
> одну раскладку для всех приложений»). Сначала проверьте, решает ли это задачу: переключение,
> сделанное программой через `WM_INPUTLANGCHANGEREQUEST` в активное окно, должно запоминаться
> системой так же, как ручное. Если да — своя память окон не нужна, достаточно правильно переключать.
> Если нет (или нужна память именно по окнам, а не по потокам) — реализовать свою:
> `HWND → раскладка`, запись при смене раскладки, восстановление при смене активного окна,
> пауза ~300 мс после смены окна (уведомления о смене раскладки в это время не записывать),
> удаление записей закрытых окон.

## 6. История буфера обмена

- Только текст. Новые сверху; повторно скопированное **поднимается наверх**, а не дублируется;
  пустой текст / одни пробелы — не сохранять. Размер: 20/50/100/200/500 (по умолчанию 50).
- **Не сохранять**:
  - содержимое, помеченное менеджерами паролей и системой как секретное/временное. На Windows это
    форматы `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory` = 0,
    `CanUploadToCloudClipboard` = 0, `Clipboard Viewer Ignore`;
  - собственные служебные записи (свой зарегистрированный формат-метка);
  - содержимое из приложений в списке исключений.
- Хранение на диске — по настройке (по умолчанию вкл.), файл в `%APPDATA%\Switchy\history.json`,
  доступ только текущему пользователю.
- **Панель** по хоткею (по умолчанию `Ctrl+Shift+V`; учтите конфликт: во многих программах это
  «вставить без форматирования»; встроенная история Windows — `Win+V`):
  - появляется у текстового курсора (иначе у указателя мыши), в пределах экрана;
  - **не забирает фокус** у приложения, куда вставляем (или возвращает его перед вставкой);
  - строка поиска сверху (без учёта регистра), список: номер 1–9, иконка приложения-источника,
    первая непустая строка элемента (длинные обрезаны), «+ ещё N стр.» для многострочных;
  - клавиши: цифры 1–9 (при пустом поиске) — вставить сразу; ↑/↓ + Enter; Ctrl+Backspace / Delete —
    удалить элемент; Esc или клик мимо — закрыть; клик по строке — вставить;
  - вставка: положить текст в буфер обмена (обычной записью — пусть он станет текущим и поднимется
    наверх в истории), закрыть панель, через ~60 мс послать Ctrl+V в исходное окно.

## 7. Хоткеи

Свой движок на низкоуровневом перехватчике клавиатуры. Типы хоткеев:

| Тип | Пример | Правило |
|---|---|---|
| Тап модификатора | тап левого Alt | нажать и отпустить модификатор ≤ 300 мс, ничего не нажимая между этим, без других модификаторов |
| Двойной тап | двойной тап правого Ctrl | два тапа одного модификатора с интервалом ≤ 350 мс |
| Одиночная клавиша | F13 | |
| Сочетание | Ctrl+Alt+Space | точное совпадение модификаторов |

- Левые и правые модификаторы различаются.
- Сработавшие одиночные клавиши и сочетания **поглощаются** (вместе с автоповтором и отпусканием).
  Тап модификатора не поглощается.
- Клик мышью и любое другое нажатие отменяют ожидаемый тап.
- Во время записи хоткея в окне настроек движок отключён.

> ⚠️ На macOS хоткей перевода по умолчанию — тап левого Option. На Windows **тап Alt** активирует
> строку меню в классических приложениях, а Win — меню «Пуск». Варианты по умолчанию для Windows:
> **тап правого Ctrl**, **двойной тап Shift**, **Pause/Break** или **Scroll Lock**. Если всё же тап Alt —
> после распознавания тапа подавлять активацию меню (послать «пустое» нажатие, например VK 0xE8,
> между нажатием и отпусканием Alt).

## 8. Настройки, исключения, прочее

Окно настроек с вкладками:
- **Перевод**: хоткей перевода; режим «Умный / По кругу»; «что переводить» (весь фрагмент / последнее слово).
- **Раскладки**: порядок круга (перетаскивание) и галочка «участвует в переборе»; таблица прямых хоткеев
  (основной + дополнительный на раскладку; меню для выбора F13–F24 без нажатия); «заодно переводить набранное».
- **Окна**: память раскладки по окнам вкл/выкл; для нового окна — «оставлять текущую» / «всегда включать X».
- **Буфер обмена**: вкл/выкл, хоткей панели, размер истории, хранить на диске, «очистить историю» (с подтверждением).
- **Исключения**: два списка приложений (добавление из запущенных или выбором .exe): «не переводить текст»
  (там не работает хоткей перевода и не ведётся буфер; прямые хоткеи только переключают раскладку) и
  «не сохранять буфер обмена».
- **Основные**: язык интерфейса (Системный / English / Русский / Українська, применяется после
  перезапуска — можно и сразу), автозапуск при входе (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`),
  версия, ссылка на проект.

Поле записи хоткея: клик → «нажмите сочетание или тапните модификатор…» → записывает сочетание, тап
или двойной тап (после первого тапа ждать ~450 мс второго); Esc — отмена; кнопка ✕ — убрать.
Предупреждать о дубликатах внутри программы и о известных системных сочетаниях.

Хранение настроек — JSON в `%APPDATA%\Switchy\settings.json`; чтение **терпимо к отсутствующим полям**
(новые настройки получают значения по умолчанию; явно снятый хоткей хранится как `null` и не
возвращается к умолчанию).

Иконка в трее показывает код текущей раскладки (EN / RU / UA); меню: список раскладок с отметкой

## 9. Windows: рекомендуемые API и подводные камни

**Стек (рекомендация):** C# / .NET 8, WinForms или WPF (трей + окно настроек), P/Invoke к Win32.
Альтернатива — Rust (`windows` crate) или C++. Тесты чистой логики — xUnit/NUnit.
Разделить код на **ядро без UI** (таблицы раскладок, буфер, движок хоткеев, умный детектор, история
буфера, настройки — всё с тестами) и **приложение** (хуки, ввод, окна).

| Задача | Windows API | Заметки |
|---|---|---|
| Перехват клавиатуры/мыши | `SetWindowsHookEx(WH_KEYBOARD_LL / WH_MOUSE_LL)` | Колбэк должен отвечать быстро (≈ < 300 мс, иначе Windows снимет хук — `LowLevelHooksTimeout`): тяжёлую работу — асинхронно в очередь. Свои события — по `dwExtraInfo`. **UIPI:** без запуска от администратора хук не видит ввод в окнах, запущенных от администратора — это нормально, документировать. |
| Список/текущая раскладка | `GetKeyboardLayoutList`, `GetKeyboardLayout(GetWindowThreadProcessId(GetForegroundWindow()))` | Раскладка — **у потока активного окна**, не у вашего процесса. Языки: `LCIDToLocaleName(LOWORD(hkl))`. Название: `GetLocaleInfoEx` / реестр `Keyboard Layouts`. |
| Переключить раскладку | `PostMessage(GetForegroundWindow(), WM_INPUTLANGCHANGEREQUEST, 0, hkl)` | `ActivateKeyboardLayout` меняет раскладку только своего потока. Для консольных окон / UWP может потребоваться адресовать окно с фокусом (`GetGUIThreadInfo().hwndFocus`). |
| Уведомление о смене раскладки | Нет глобального события | Опрашивать раскладку активного потока (~150–250 мс) или ловить `WM_INPUTLANGCHANGE` своих окон. |
| Клавиша → символ | `ToUnicodeEx(vk, scan, keyState, buf, n, flags, hkl)` | Передавать `hkl` нужной раскладки. Флаг `0x4` (не менять состояние мёртвых клавиш, Win10 1607+), иначе собьёте dead-key состояние пользователя. |
| Символ → клавиша | `VkKeyScanExW(ch, hkl)` или обратная таблица по `ToUnicodeEx` | Обратную таблицу лучше строить самим (как в разделе 2.4). |
| Ввод текста | `SendInput` с `KEYEVENTF_UNICODE` | Для символов вне BMP — суррогатные пары двумя событиями. Backspace — `VK_BACK`. Перед вводом дождаться отпускания модификаторов (`GetAsyncKeyState`). |
| Выделенный текст | UI Automation: `IUIAutomation.GetFocusedElement` → `TextPattern.GetSelection()` | Запасной путь — Ctrl+C с сохранением/восстановлением буфера (все форматы). |
| Позиция текстового курсора | `GetGUIThreadInfo` (`rcCaret` + `ClientToScreen`); UIA `TextPattern2.GetCaretRange` / `GetBoundingRectangles` | Многие приложения (Chromium, Electron) не дают системный caret — тогда UIA, иначе позиция мыши. Учитывать DPI (`SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`). |
| Смена активного окна | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` | Окна внутри одного приложения — тоже приходят как foreground. Закрытие окна — `EVENT_OBJECT_DESTROY` или проверка `IsWindow`. |
| Буфер обмена | `AddClipboardFormatListener` → `WM_CLIPBOARDUPDATE` | Событийно, без опроса. Источник: `GetClipboardOwner` → процесс; или активное приложение. Форматы-исключения — `RegisterClipboardFormat` + `IsClipboardFormatAvailable`. Буфер может быть занят другим процессом — повторять `OpenClipboard` с паузами. |
| Проверка орфографии | `ISpellCheckerFactory` (Windows 8+) | Словари есть только для установленных языков (языковые пакеты / «Проверка правописания» в доп. компонентах). Проверить `IsSupported("ru-RU")`, `"uk-UA"`, `"en-US"`; если словаря нет — для этой раскладки `spell = 0` и сообщить в настройках. |
| Распознавание языка | Встроенного аналога macOS NLLanguageRecognizer почти нет | Варианты: (а) ELS «Microsoft Language Detection» (`MappingRecognizeText`, есть с Windows 7); (б) небольшая модель символьных триграмм для en/ru/uk, встроенная в программу (десятки КБ, без сети); (в) только словарь (вес `spell` = 0.9, `letters` = 0.1) и тай-брейкер по буквам, характерным для языка (`ы э ъ ё` → ru, `і ї є ґ '` → uk). Главное — пройти тесты из 3.1. |
| Трей | `Shell_NotifyIcon` / `NotifyIcon` | Значок с текстом раскладки — рисовать иконку на лету. |
| Панель без кражи фокуса | Окно со стилями `WS_EX_TOOLWINDOW` + `WS_EX_TOPMOST` | Самое простое: запомнить исходное окно, показать панель (она получит фокус), при выборе — `SetForegroundWindow(исходное)`, затем Ctrl+V. Учитывать ограничения `SetForegroundWindow` (работает, т.к. хоткей — последнее событие ввода; иначе `AttachThreadInput`). |
| Автозапуск | `HKCU\...\CurrentVersion\Run` | |
| Подпись | — | Без сертификата SmartScreen предупреждает при запуске — описать в README «Подробнее → Выполнить в любом случае». |

**Безопасность и приватность:** программа — по сути кейлоггер по механизму, поэтому: буфер набора
только в памяти; ничего не отправлять в сеть; не трогать поля паролей (в Windows их можно определить
через UIA `IsPassword` — в них не вести буфер и не переводить); историю буфера хранить с правами только
текущего пользователя; прямо написать это в README.

## 10. Порядок реализации (этапы)

7. История буфера обмена и панель.
8. Исключения по приложениям, пауза, иконка, установщик/портативная сборка.
